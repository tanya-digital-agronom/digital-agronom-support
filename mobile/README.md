# Цифровой Агроном — мобильная CRM (Android / iPhone)

Исходная веб-CRM находится в `../crm.html`. Мобильное приложение строится **из этого же файла**, поэтому обращения, задачи, история, план и календарь внедрения, закупки, материалы, отчёты, журнал действий, администрирование и роли остаются общими. База данных и авторизация — существующий Supabase. Здесь нет отдельной мобильной базы и нет дублирования бизнес-логики.

## Уже реализовано

- **Один исходный интерфейс для Android и iOS:** Capacitor 8, JavaScript и CSS.
- **Мобильная навигация:** нижние вкладки «Главная», «Обращения», «Задачи», «Материалы» и «Ещё»; остальные разделы в меню «Ещё».
- **Адаптивные экраны:** формы, фильтры, календари, таблицы обращений и задач превращаются в компактные карточки на телефонах; на планшетах сохраняется расширенный интерфейс.
- **Supabase:** те же учётные записи, роли и политики доступа. Никаких секретных `service_role` ключей в приложении.
- **Уведомления внутри CRM:** колокольчик о просрочках из исходной системы (пока приложение открыто), синхронизация с Supabase.
- **Файлы:** мобильное меню «Поделиться / Сохранить» для скачанных вложений, а также CSV/JSON. Открытие подписанных ссылок через системный браузер.
- **PDF:** попытка преобразовать существующий печатный отчёт в PDF и открыть системное меню сохранения; если конкретный WebView не поддержит рендеринг, доступен HTML-отчёт.
- **Нативный Android Back:** возврат к главной странице из разделов, закрытие меню, сворачивание с главной.
- **Фирменная иконка:** заготовка генерируется из фавиконки исходной CRM (перед релизом нужна новая иконка высокого разрешения).

## Запуск

Требуется **Node.js 22+** и подключение к интернету для загрузки npm-пакетов.

```bash
cd mobile
npm install
npm run build
npm run verify
```

Папка `mobile/www` генерируется автоматически из `../crm.html`, `src/mobile.css` и `src/mobile-ui.js`. Редактировать копию `www/index.html` вручную не нужно: изменения исчезнут при следующей сборке.

### Android

Нужны Android Studio и Android SDK.

```bash
npm run android:init
npx cap run android
```

Или откройте проект в Android Studio командой `npm run android:open`, затем соберите APK в меню **Build > Build APK(s)**. После изменения веб-CRM обновляйте нативный проект командой `npm run sync`.

### iPhone / iOS

Нужен **Mac с Xcode 26+**. Для установки на устройство и для TestFlight нужна Apple Developer signing configuration.

```bash
npm run ios:init
npx cap run ios
```

Для открытия в Xcode: `npm run ios:open`. Чтобы поставить на настоящий iPhone или опубликовать в App Store, потребуется выбрать Apple Developer Team и собственный Bundle Identifier в `capacitor.config.json` перед подписанием.

### Сборка с GitHub Actions

В репозитории есть ручной workflow **Build mobile preview (Android + iOS)**: вкладка **Actions → Build mobile preview (Android + iOS) → Run workflow**.

Он рассчитан на создание двух артефактов:

1. **Android debug APK** — для тестовой установки на Android; не является подписанным релизом Play Store.
2. **iOS Simulator app** — для проверки в симуляторе Xcode; **не является IPA для установки на реальный iPhone**, так как реальному устройству нужна подпись Apple.

Workflow добавлен, но успешная облачная сборка ещё не подтверждена. Для App Store/TestFlight нужна отдельная настройка сертификатов и профилей.

## Что ещё нужно проверить перед выпуском

1. Логин и сохранение сессии на настоящем Android и iPhone.
2. Загрузка фотографий, документов, презентаций в Supabase Storage и получение подписанных файлов.
3. Генерация, переносы страниц и сохранение больших PDF-отчётов в системное приложение «Файлы».
4. Уведомления при открытом приложении, обновление данных после сворачивания.
5. Тесты прав администратора, специалиста поддержки и наблюдателя на двух устройствах одновременно.
6. Отдельный качественный значок, splash-screen, юридические документы и публикационные параметры.
7. Настоящие **push-уведомления при закрытом приложении** — отдельный этап с APNs/FCM и серверной отправкой, их здесь пока нет.
8. Для работы без сети нужны локальная очередь и разрешение конфликтов изменений; сейчас данные по-прежнему зависят от Supabase и доступа в интернет.

## Структура

```text
mobile/
  capacitor.config.json
  package.json
  src/
    manifest.webmanifest
    mobile.css
    mobile-ui.js
    native-bridge.js
  scripts/
    build.mjs
    verify.mjs
  www/                # генерируется, не коммитится
  assets/icon.png     # генерируется, логотип-заготовка
  android/             # генерируется Capacitor CLI
  ios/                 # генерируется Capacitor CLI
```

**Важно:** сначала приложение создано как общий, обновляемый нативный проект. На текущем этапе ещё нет подписанного APK/AAB релиза и iOS IPA. Смена `../crm.html` отражается в мобильном приложении после `npm run sync` и сборки нового пакета; в уже установленном APK изменения не появляются автоматически.
